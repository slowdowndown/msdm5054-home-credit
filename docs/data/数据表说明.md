# 数据表与关联键

以下按本地官方 CSV 文件及随附字段字典整理。V0 仅使用申请主表。TARGET=1 表示比赛定义的还款困难。

| 文件 | 内容及粒度 | 关联方式 |
|---|---|---|
| application_train.csv | 每行一个有标签的当前申请，含 TARGET | SK_ID_CURR 为申请编号 |
| application_test.csv | 每行一个待预测申请，无 TARGET | SK_ID_CURR；与训练表分开处理 |
| bureau.csv | 客户在其他机构的历史信贷记录，一位客户可有多笔 | SK_ID_CURR 关联申请；SK_ID_BUREAU 标识信贷记录 |
| bureau_balance.csv | bureau 信贷记录的月度状态 | SK_ID_BUREAU 关联 bureau；先聚合月度，再聚合至客户 |
| previous_application.csv | 客户以前向 Home Credit 申请的记录 | SK_ID_CURR 关联申请；SK_ID_PREV 标识历史申请 |
| POS_CASH_balance.csv | 历史 POS 和现金贷款的月度余额及状态 | SK_ID_PREV、SK_ID_CURR；需聚合 |
| credit_card_balance.csv | 历史信用卡的月度余额和使用情况 | SK_ID_PREV、SK_ID_CURR；需聚合 |
| installments_payments.csv | 历史贷款的分期应还和实际付款记录 | SK_ID_PREV、SK_ID_CURR；一笔贷款有多条记录 |
| HomeCredit_columns_description.csv | 各表字段含义字典 | Table、Row、Description 等说明列，不是训练样本 |
| sample_submission.csv | Kaggle 提交模板及测试编号顺序 | SK_ID_CURR、TARGET；TARGET 是格式示例，不是真实标签 |

“7 张表”通常将申请训练/测试视为一个逻辑主表，加六种辅助记录表；实际 CSV 文件还包括字段字典和提交模板。

不能将多行历史明细直接连接到主表后当作独立申请训练，否则会重复客户、改变样本权重。后续特征应先按申请编号聚合，再做一对一连接；检查行数不变、编号唯一，保留无历史记录的客户，并避免使用预测时尚不可获得的信息。
