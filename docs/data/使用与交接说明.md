## 放置和运行

将本包的 docs/、notebooks/、src/、results/ 合并到仓库对应目录。同名文件先比较，不覆盖组员成果。保留组长 README、CONTRIBUTING、.gitignore 和根 requirements.txt。

1. 从 https://www.kaggle.com/c/home-credit-default-risk/data 下载并解压原始 CSV 到仓库 `data/raw/`。不要修改原始文件。
2. 使用 Python 3.12 创建并激活独立环境（`python3.12 -m venv .venv`；macOS/Linux 用 `source .venv/bin/activate`，Windows 用 `.venv\Scripts\activate`）。安装 A 部分依赖：`python -m pip install -r requirements/base.txt`，将该环境选为 Notebook 内核。主要依赖已固定到本次验收版本。完整 macOS ARM64 / Python 3.12.14 环境记录在 requirements/locks/baseline-macos-arm64.txt；其他平台使用 requirements/base.txt，避免直接安装平台专用包。安装后执行 `python -m ipykernel install --sys-prefix --name homecredit-v0 --display-name "Home Credit V0"`，再用 `python -m jupyterlab` 启动并选择该内核。
3. 从仓库根目录启动 Jupyter，打开 `notebooks/01_data_and_baseline.ipynb`，依次运行全部单元。也支持从 notebooks/ 启动。Notebook 是 V0 的统一入口。
4. Notebook 会调用 `src/data_pipeline.py` 中的共享 fixed_split 函数，核对训练文件 SHA-256，然后生成并复用固定划分。也可以在根目录单独执行 `python src/reproduce_split.py`。
5. 生成文件保存在 `data/processed/v0/`，由现有 `.gitignore` 排除。这里包含划分、预处理配置、模型、验证预测、汇总表和图。`results/baseline/` 是本次完整验收的汇总快照（旧结果存于 results/baseline/history/pre_refactor/），运行 Notebook 不会自动覆盖它；新结果审核后再更新快照。
6. 最后一格生成 `results/submissions/submission_v0.csv` 并校验。已有同名文件时停止，避免覆盖。此步骤不联网提交。

## 统一的数据版本和划分

`data_manifest_v0.json` 记录此次原始 CSV 的字节数与 SHA-256；`split_protocol.json` 记录固定划分依据。V0 使用申请主表，不合并历史表。训练主表 307,511 行，测试主表 48,744 行。按 TARGET 分层，seed=42，80%/20%：训练 246,008 行，验证 61,503 行。

加入新特征时必须按 SK_ID_CURR 对齐，保留此划分，不按自己的行号随机重拆。若训练文件校验失败，应核实数据版本，不能简单修改指纹绕过检查。V1 为同一划分下添加基础特征的版本；V2 为可选增强版本，当前未实现。

## 预处理与模型边界

不把 SK_ID_CURR 或 TARGET 当特征。DAYS_EMPLOYED=365243 转为缺失，四个金额字段 log1p；数值中位数填补、缺失指示和标准化，类别填补及独热编码。所有学习参数只在训练子集拟合。`preprocessing.json` 是本次验收配置快照，实际执行逻辑在 src/data_pipeline.py 中。

新版 baseline_pipeline.joblib 已包含清洗。载入前将 src 加入 Python 模块路径，直接对原始主表行调用 predict_proba；不要再调用 deterministic_clean。旧版模型接口与新版不同，不可混用。该模型在 80% 训练子集拟合，本次验证 ROC-AUC 0.751239。生成的提交文件也使用这同一基线，证明 V0 流程完整，不宣称是最终竞赛模型。全量重训和最终模型选择应与 ZHANG Yajing 对接，不能把全量拟合后的训练分数当验证分数。

## 共享模块和模型调用

`src/data_pipeline.py` 提供 load_main_tables、fixed_split 和 HomeCreditPreprocessor；`src/baseline.py` 提供 build_baseline。预处理的列筛选、填补和编码仅在 fit 中学习。模型负责人可把预处理器与其他模型放入同一个 sklearn Pipeline，再用于每折交叉验证。

从仓库根目录运行：

```python
from pathlib import Path
import sys
root = Path.cwd()
sys.path.insert(0, str(root / "src"))
from data_pipeline import load_main_tables, fixed_split
from baseline import build_baseline
train, test, dictionary = load_main_tables(root)
fit_idx, val_idx, assignments = fixed_split(root, train)
model = build_baseline(seed=42)
model.fit(train.iloc[fit_idx], train.TARGET.iloc[fit_idx])
prob = model.predict_proba(train.iloc[val_idx])[:, 1]
```

模型只从输入中提取特征，排除 TARGET 和 SK_ID_CURR。加载保存模型时也需要 src 下的 data_pipeline 模块。只加载自己或可信组员生成的模型。
